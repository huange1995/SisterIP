# 脚本 · 脚本文案（② 脚本段 · copy[] 原子，嵌在策划案里）

> **文案原子先于分镜。** ② 脚本段管**片内文案**——短片里的**字幕**（subtitle）与**旁白**
> （voiceover）原子，作为 `copy[]` 嵌在①策划段的**策划案 JSON**（`../策划/01-策划.md`）里，
> 一条一条绑到分镜（`scene`）。分镜只是文案的画面支撑。
>
> **脚本 ≠ 发帖配文**：发帖配文（小红书/朋友圈的社交文案）归 `../发帖文案.md`，**不入片、不进图**；
> 本层只管**片内**字幕/旁白（会被 compose 烧成字卡 / 合成 TTS 旁白）。

## 一、copy[] 原子 schema

```json
"copy": [
  {"id": "c1", "text": "值夜班，是她的主旋律", "mode": "subtitle", "tone": "冷", "scene": "s1"},
  {"id": "c2", "text": "急什么，天又塌不下来。", "mode": "voiceover", "tone": "媚", "scene": "s3"}
]
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 唯一标识（省略自动 `c1`、`c2`…；重复会校验报错） |
| `text` | ✅ | 文案内容（一句一个原子） |
| `mode` | ✅ | `subtitle`（**字幕**，画面里的话）｜`voiceover`（**旁白**，画外音） |
| `tone` | | 语气（冷/媚/飒…）——评审与挑音色用 |
| `scene` | | **绑到某镜**（`shot.id`）；不绑则本层只负责「文字」，不入片 |

> 校验（produce 自动做）：`mode` 必须是 `subtitle` 或 `voiceover`；`scene` 必须指向存在的镜；
> 反向——分镜里 `shot.copy` 必须指向存在的 `copy.id`。

## 二、数据流（脚本 → 成片）

```
策划案 copy[] → produce --emit → 分镜表：scenes[].text（烧字卡）+ audio.voiceover[]（TTS 旁白）
→ compose → 字幕烧录 + 旁白按镜对齐混音 → 成片
```

- `subtitle` 原子 → 分镜表该镜的 `text` → compose 烧字卡（PIL + 微软雅黑）+ 导出 SRT。
- `voiceover` 原子 → 分镜表 `audio.voiceover[]` → compose 用火山 TTS 合成旁白，delay = 该镜起始秒。

## 三、怎么写（脚本门的设计规范）

1. **先文案后镜头**：策划案里 `copy[]` 写在 `shots[]` 之前——镜头是文案的画面支撑。
2. **一句一个原子**：`text` 是独立语义单位，别把两句话塞一条；跨镜就拆两条各绑各的镜。
3. **字幕 vs 旁白分清**：字幕是「画面里的话」（短、可配动作）；旁白是「画外音」（可长、走情绪）。
4. **绑镜**：`scene` 指向承载这条文案的镜；钩子句（hook 镜）优先给旁白。
5. **带「顾遥味」**：短句、句号、慢、话留一半；口癖常驻（「急什么，天又塌不下来。」）。

## 四、脚本门（文案合规，成片前必过）

- **媚而不俗**：字幕/旁白先过底线——低俗 / 引导词 / 违禁词不入片（`../校验.md` 通用门）。
- **短句留白**：不喊麦、不用感叹号轰炸、不用网梗（与 `../发帖文案.md` 语气同守）。
- **与画面同档**：文案的情绪档位（冷/媚/飒）与所在镜的档位一致，跨档违和。
